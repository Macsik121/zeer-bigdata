Эта ошибка указывает на то, что сетевое соединение между вашей виртуальной машиной и Windows успешно установилось (порт 3376 открыт, файрвол пропустил пакет), но сама MariaDB заблокировала вход по соображениям безопасности.
Главная улика кроется в тексте ошибки: user 'root'@'localhost'. Обратите внимание на @'localhost'. Несмотря на то, что вы подключаетесь с виртуальной машины, MariaDB почему-то считает, что вы стучитесь локально, либо, что более вероятно, в настройках прав пользователя root жестко прописано ограничение — пускать только изнутри Windows (localhost). По умолчанию в целях безопасности пользователю root запрещено подключаться с любых внешних IP-адресов.
Вот пошаговое руководство, как решить эту проблему и разрешить доступ.
Шаг 1. Разрешить MariaDB принимать внешние подключения
Убедитесь, что MariaDB на Windows вообще готова слушать запросы из сети, а не только от самой себя.
1. На Windows найдите конфигурационный файл MariaDB (обычно это my.ini в папке установки, например, C:\Program Files\MariaDB [версия]\data\my.ini или в корневой папке).
2. Найдите секцию [mysqld] и строку bind-address.
3. Убедитесь, что она закомментирована (стоит знак #) или изменена следующим образом:ini
[mysqld]
bind-address = 0.0.0.0
port = 3376
Use code with caution.
Значение 0.0.0.0 означает, что сервер будет слушать подключения на всех сетевых интерфейсах, включая сеть от виртуальной машины.
4. Если вы вносили изменения, перезапустите службу MariaDB через диспетчер задач Windows или оснастку «Службы».
Шаг 2. Дать права пользователю root на вход из виртуальной машины
Вам нужно явно разрешить пользователю root подключаться с IP-адреса вашей виртуальной машины (или с любого IP-адреса вообще).
1. Находясь на Windows, откройте консоль MariaDB локально (через HeidiSQL, DBeaver или командную строку Windows):cmd
mysql -u root -p -P 3376
Use code with caution.
2. Выполните SQL-запрос, чтобы посмотреть текущие ограничения для root:sql
SELECT user, host FROM mysql.user WHERE user='root';
Use code with caution.
Вы, скорее всего, увидите строки root | localhost или root | 127.0.0.1. Это значит, что извне входить под root нельзя.
3. Создайте или обновите пользователя root, разрешив ему доступ со всех хостов (знак % означает «любой IP-адрес»):sql
-- Для MariaDB синтаксис создания/изменения прав выглядит так:
GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' IDENTIFIED BY 'ваш_пароль' WITH GRANT OPTION;
Use code with caution.
Если вы хотите сделать подключение более безопасным, вместо % укажите конкретный IP-адрес вашей виртуальной машины (например, 'root'@'192.168.56.101').
4. Примените изменения в памяти сервера:sql
FLUSH PRIVILEGES;
Use code with caution.
Шаг 3. Подключение из виртуальной машины
Теперь возвращайтесь в терминал вашей виртуальной машины. При подключении через утилиту mysql вам нужно обязательно явно указать IP-адрес Windows-хоста через флаг -h.
Если вы не укажете хост или напишете localhost, клиент попытается найти MariaDB внутри самой виртуальной машины.
Команда для подключения из ВМ должна выглядеть так:
bash
mysql -u root -p -h <IP_АДРЕС_ВАШЕГО_WINDOWS> -P 3376
Use code with caution.
(Замените <IP_АДРЕС_ВАШЕГО_WINDOWS> на реальный IP-адрес вашего компьютера в виртуальной или локальной сети, например 192.168.56.1 или 10.0.2.2 в зависимости от настроек сети ВМ).
После ввода пароля подключение должно успешно установиться.

1. Главная ошибка: Вы подключаетесь не к тому IP
В команде вы указали: mysql -u root -p -h 192.168.1.1 --port=3376
Согласно вашему ipconfig:
• 192.168.1.1 — это Основной шлюз (ваш домашний Wi-Fi роутер). MariaDB установлена не на роутере, поэтому там вы получаете железный отказ.

2. Почему не работает и с 192.168.1.108? (Ошибка 2003 / 101)
Ошибка Can't connect... (101) (Network is unreachable / Connection timed out) на правильном IP означает, что виртуальная машина физически не может достучаться до порта 3376 на Windows. С правами пользователя в MariaDB теперь всё отлично (root | % успешно создался). Проблема на уровне сети.
Пожалуйста, проверьте два главных фактора:
А. Настройка сети в Виртуальной Машине (Самое вероятное)
Чтобы ваша ВМ видела адрес 192.168.1.108, она должна находиться в той же подсети, что и ваш ноутбук.
1. Зайдите в настройки вашей Виртуальной Машины (VirtualBox / VMware) -> раздел Сеть (Network).
2. Тип подключения (Attached to) должен быть строго Сетевой мост (Bridged Adapter), а в качестве имени адаптера выбрана ваша беспроводная карта (Wi-Fi).
3. Если там сейчас стоит NAT, ваша ВМ изолирована внутри ноутбука и не сможет достучаться до его внешнего Wi-Fi адреса 192.168.1.108 напрямую.
Б. Брандмауэр Windows (Файрвол)
Windows по умолчанию блокирует все входящие подключения на нестандартные порты из локальной сети.
1. На Windows откройте Монитор брандмауэра защитника Windows в режиме повышенной безопасности (можно найти через поиск в меню Пуск, набрав wf.msc).
2. Нажмите Правила для входящих подключений (Inbound Rules) -> Создать правило (New Rule).
3. Выберите Для порта (Port) -> Далее -> Протокол TCP, в строке «Определенные локальные порты» укажите 3376.
4. Выберите Разрешить подключение (Allow the connection) -> Далее -> Отметьте галочками все профили (Доменный, Частный, Публичный).
5. Дайте правилу имя (например, MariaDB 3376) и нажмите «Готово».

Если пинг не идет вообще (100% packet loss), это означает, что ваша виртуальная машина сейчас находится в полной сетевой изоляции от основного компьютера (хоста). Они буквально «не видят» друг друга в сети. Права в MariaDB настроены верно, теперь нужно исправить этот сетевой глухой затык.
Вот две основные причины и способы их решения:
Причина 1. Виртуальная машина находится в сети NAT (Наиболее вероятно)
Если в настройках виртуальной машины (в VirtualBox или VMware) тип подключения сети установлен как NAT, то ВМ прячется за внутренним виртуальным роутером. Она может выходить в интернет, но не видит локальный IP-адрес вашего Windows (192.168.1.108).
Как исправить:
1. Выключите виртуальную машину (или переведите в режим паузы).
2. Откройте настройки этой ВМ в менеджере (например, в VirtualBox).
3. Перейдите в раздел Сеть (Network).
4. В поле «Тип подключения» (Attached to) измените значение с NAT на Сетевой мост (Bridged Adapter).
5. В поле «Имя» (Name) выберите ваш беспроводной адаптер Wi-Fi (тот самый, через который Windows подключен к домашнему роутеру).
6. Запустите виртуальную машину.
7. Внутри терминала ВМ проверьте её новый IP-адрес с помощью команды ip a или ifconfig. Она должна получить адрес из той же домашней сети (что-то вроде 192.168.1.X).
Причина 2. Брандмауэр Windows блокирует ICMP (Пинг)
Даже если сеть настроена правильно, Брандмауэр Windows по умолчанию запрещает отвечать на пинги в целях безопасности. Компьютер получает запрос от ВМ, но сознательно игнорирует его, прикидываясь «мертвым».
Как исправить быстро (для проверки):
Чтобы подтвердить, что дело в брандмауэре, временно отключите его на Windows:
1. Откройте Пуск -> введите «Брандмауэр Защитника Windows».
2. В левой колонке нажмите «Включение и отключение брандмауэра Защитника Windows».
3. Отключите его для частной и общественной сетей и нажмите ОК.
4. Попробуйте снова запустить ping -c 3 192.168.1.108 из виртуальной машины.
Если пинг пошел и MariaDB подключилась — обязательно включите брандмауэр обратно и создайте в нем разрешающее правило для порта 3376 (как мы описывали в прошлом шаге), а также для «Общего запроса эхо (ICMPv4-In)», чтобы работал пинг.
