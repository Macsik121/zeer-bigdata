# План создания домашней Big Data инфраструктуры Zeer Marketplace v2.1

# 1. Обзор проекта

## Цель проекта

Создать домашнюю распределенную Big Data платформу для обработки данных маркетплейса Zeer.

Система должна обеспечивать:

* сбор пользовательских событий;
* обработку логов приложения;
* анализ ошибок и crash-событий;
* хранение данных в Data Lake;
* выполнение распределенных вычислений;
* подготовку аналитических витрин;
* доступ через API, SQL и BI-инструменты.

Архитектура строится на Apache Hadoop ecosystem:

* HDFS;
* YARN;
* Spark;
* Kafka;
* ZooKeeper;
* Hive;
* Node.js API;
* Grafana/Prometheus.

---

# 3. Аппаратная архитектура

## 3.1 Общая схема

Используется:

* 1 рабочий ноутбук как Master Node;
* 3 физических ПК как DataNode.

Архитектура:

```
                    WORK LAPTOP

                    MASTER NODE

        ---------------------------------

        NameNode

        ResourceManager

        Hive Metastore

        Spark History Server

        Node.js API

        Monitoring


                    |
                    |
              Ethernet LAN 1Gb


================================================


       PC-1              PC-2              PC-3


    DATANODE          DATANODE          DATANODE

    NodeManager       NodeManager       NodeManager

    Spark Worker      Spark Worker      Spark Worker

    Kafka Broker      Kafka Broker      Kafka Broker

    ZooKeeper         ZooKeeper         ZooKeeper
```

# 7. Выбор компонентов

## Hadoop

Используется:

Apache Hadoop 3.x

Компоненты:

* HDFS;
* YARN;
* MapReduce.

---

## Spark

Используется:

Apache Spark 3.x.

Режим запуска:

```
Spark on YARN
```

Не используется:

```
Spark Standalone
```

Причина:

YARN отвечает за распределение ресурсов между приложениями.

---

## Kafka

Используется:

Apache Kafka.

Архитектура:

```
Broker 1

Broker 2

Broker 3
```

Каждый DataNode содержит Kafka Broker.

---

## ZooKeeper

Используется:

3-node ensemble:

```
zeer-worker1

zeer-worker2

zeer-worker3
```

Назначение:

* координация Kafka;
* управление кластером.

# 9. HDFS архитектура

Схема:

```
                NameNode

                    |

     --------------------------------

     |              |              |

 DataNode1      DataNode2      DataNode3
```

---

## Репликация

Настройка:

```
dfs.replication=2
```

Причина:

3 DataNode позволяют пережить отказ одного узла.

При этом сохраняется больше полезного места.

---

Пример:

Файл:

```
events.parquet
```

будет размещен:

```
Block A:

DataNode1

DataNode2
```

или:

```
DataNode2

DataNode3
```
