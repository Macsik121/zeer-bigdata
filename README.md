# Тема дипломной работы

## **Название:**

**"Разработка и внедрение распределённой системы обработки и анализа логов маркетплейса на базе Apache Hadoop экосистемы"**

### Альтернативный вариант:

**"Проектирование и реализация Lambda-архитектуры для обработки больших данных пользовательских событий веб-сервиса"**

---

## **Краткое описание проекта**

Проект представляет собой комплексное решение для сбора, хранения, обработки и анализа логов онлайн-маркетплейса Zeer Marketplace с использованием технологий Apache Hadoop экосистемы на физическом кластере из 4 узлов (1 Master + 3 Worker).

### **Ключевые особенности:**
- Физическая инфраструктура на базе домашнего кластера (LGA 1155, бюджетное решение)
- Обработка трёх типов логов: действия пользователей (Action Logs), сбои системы (Crash Logs), события инжекции (Inject Logs)
- Lambda-архитектура: batch-обработка (HDFS + Spark) + streaming (Kafka + Spark Structured Streaming)
- 28 бизнес-метрик по 5 доменам (бизнес, продукт, технические, безопасность, конвейер)
- Machine Learning-конвейер для предсказания сбоев и оттока пользователей

---

## **Актуальность**

### **1. Техническая актуальность:**
- **Масштабирование систем логирования**: современные веб-сервисы генерируют миллионы событий в сутки, требующие обработки в real-time и batch режимах
- **Анализ пользовательского поведения**: необходимость извлечения ценных инсайтов из больших объёмов неструктурированных данных
- **Proactive monitoring**: предсказание проблем (сбои, отток) до их критического влияния на бизнес

### **2. Бизнес-актуальность:**
- **Оптимизация конверсии**: понимание воронок пользователей (регистрация → покупка) позволяет повысить конверсию на 15-30%
- **Снижение оттока** (Churn): предсказание оттока даёт возможность удержать 20-40% потенциально уходящих клиентов
- **Fraud detection**: детекция мошенничества (шаринг аккаунтов, брутфорс) экономит до 10-15% выручки

### **3. Образовательная актуальность:**
- Демонстрация полного цикла разработки Big Data решения: от физической инфраструктуры до ML-моделей
- Применение современных технологий (Hadoop, Kafka, Spark, ML) в реальном проекте
- Решение практических инженерных задач (охлаждение, безопасность, отказоустойчивость)

## **Научная новизна и практическая значимость**

### **Научная новизна:**
1. **Гибридная архитектура на бюджетном оборудовании**: адаптация корпоративных решений (Lambda-архитектура) для домашнего кластера с ограниченными ресурсами
2. **Многоуровневая система детекции аномалий**: комбинация streaming (near-real-time alerts) и batch (глубокий анализ) для security-метрик
3. **Контекстно-зависимые ML-модели**: классификатор крэшей с embedding'ами stack trace и таксономией Windows-исключений

### **Практическая значимость:**
1. **Экономическая эффективность**: 
   - Стоимость кластера ~50-70 тыс. руб. против 300+ тыс. руб. за облачное решение
   - Окупаемость через снижение оттока и оптимизацию конверсии за 6-8 месяцев
2. **Масштабируемость**: архитектура позволяет добавлять узлы без переписывания кода
3. **Применимость**: решение адаптируется для любого веб-сервиса с логированием событий (e-commerce, SaaS, gaming)

## **Цели и задачи**

### **Цель работы:**
Разработать и внедрить отказоустойчивую распределённую систему обработки больших данных логов маркетплейса, обеспечивающую real-time мониторинг и batch-аналитику с latency < 5 минут для streaming и < 1 часа для batch.

### **Задачи:**

#### **Инфраструктурные:**
1. Спроектировать и собрать физический 4-узловой кластер с системой охлаждения и электробезопасности
2. Развернуть Apache Hadoop экосистему (HDFS, YARN, Kafka, Spark, ZooKeeper, Flume, Hive) через ADCM
3. Настроить сетевую архитектуру, репликацию данных (RF=2) и fault tolerance

#### **Архитектурные:**
4. Спроектировать Lambda-архитектуру с разделением на streaming (Kafka + Spark Structured Streaming) и batch (HDFS + Spark SQL) слои
5. Разработать схемы данных для 3 типов логов (Action, Crash, Inject) с валидацией через Data Quality Gate
6. Реализовать ELT-конвейер (Extract → Load → Transform) с партиционированием по дате и контролем качества

#### **Аналитические:**
7. Определить и реализовать 28 метрик по 5 доменам (бизнес, продукт, технические, безопасность, конвейер данных)
8. Создать витрины данных (Data Mart) для бизнес-дашбордов (Grafana, Superset)
9. Разработать систему алертов с runbook'ами для каждой critical-метрики

#### **ML/AI:**
10. Разработать Feature Engineering pipeline (user/session/crash features)
11. Обучить 3 ML-модели: Crash Classifier (multi-class), Injection Failure Predictor (binary), User Churn Predictor (binary)
12. Развернуть FastAPI inference service для real-time предсказаний

## **Технологический стек**

### **Инфраструктура:**
- Ubuntu Server 22.04 LTS
- Кластер: 1 Master (192.168.1.5) + 3 Workers (192.168.1.10-12)
- ArenaData Cluster Manager (ADCM) + ArenaData Hyperwave (ADH)

### **Hadoop Ecosystem:**
- HDFS (распределённое хранилище, RF=2)
- YARN (управление ресурсами)
- ZooKeeper (координация)
- Kafka (потоковая обработка, 3 брокера)
- Flume (сбор логов)
- Spark (batch + streaming обработка)
- Hive (SQL-on-Hadoop)

### **Аналитика и ML:**
- Spark MLlib (обучение моделей)
- FastAPI (inference service)
- Grafana + Prometheus (мониторинг)
- Apache Superset (BI-дашборды)

### **Разработка:**
- Python 3.9+ (ETL, ML pipeline)
- Scala 2.12 (Spark jobs)
- Node.js 14+ (API collector)
- Git (версионирование)

## **Риски и ограничения**

### **Технические риски:**
1. **Ограниченная ёмкость дисков**: 
   - Текущая: 3 × 512 ГБ = 768 ГБ полезных (с RF=2)
   - Retention: Raw 30 сут, Core 90 сут, Mart 365 сут
   - Требуемая для NFR-3 "90 сут raw": ~1.2 ТБ
   
2. **Отсутствие NameNode HA**: 
   - Отказ Master-ноды останавливает весь кластер
   - Восстановление: ~30 мин (RTO)
   
3. **Метрика D1 (шаринг) разделена**: 
   - Streaming: всплеск за час
   - Batch: точное недельное значение

### **Организационные риски:**
- Зависимость от домашней инфраструктуры (электричество, охлаждение)
- Требуется регулярное обслуживание (чистка, мониторинг температуры)
